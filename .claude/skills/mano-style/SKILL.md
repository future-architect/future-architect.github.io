# 真野隼記の文体

2025〜2026年の28本（Go リリース連載・ツール試用・設計ガイドライン公開・Slack 発のエッセイ）から
抽出した。数字はその実測。記事の種類で型が違うので、まず「どの型か」を決めてから書く。

## 声

- **ですます調。1文は平均54字、段落は1〜3文**（970段落のうち1文が46%、2文が29%、4文以上は6%）。
  長い段落を書きそうになったら箇条書きに割る
- **一人称は「私」。「僕」「筆者」は使わない**（私40回、筆者1回、僕0回）
- **意見は必ず自分のものとして、やわらかく言い切る。** 「〜と思います」（72回）「〜でしょう」（100回）
  「〜かもしれません」「〜と良さそうです」「〜のではないでしょうか」。
  断定は仕様・事実のときだけ。「個人的には」（14回。強めるときは「超個人的には」）で
  私見を前置きする
- **軽い感情を1記事に数か所、短く挟む。** 「ありがたいですね」「素敵！」「不憫な子」
  「少しドキドキのアップデートです」「拍子抜けしました」「ちと面倒です」「この感動を伝えさせてください」。
  「嬉しい」は13回出る。**連発しない。** 本文は淡々と事実を積み、締めや節の末尾で1つ出す
- **苦労したところを正直に書く。** 「コードを動かしてみるまでピンと来ませんでした」
  「〜あたりで時間がかかりました」「設定の作り込みの甘さはご了承ください」。
  できたことだけを並べない
- **丸括弧の補足を多用する**（15字以上の括弧書きが154回）。「（他にも見落としがあるかもしれません）」
  「（場合によっては利用者）」のように、本文の流れを切らずに留保・例・脱線を入れる
- **話し言葉の疑問を地の文に混ぜる**（「？」138回）。「今となっては不要では？みたいな声」
  「競合？となりえそうな周辺ツール」「どうせあまりオシャレじゃないんでしょう？..と、あまり期待していなかった」
- **節の頭で短く切り替える。** 「さて、Go 1.26です。」「では、どうすればよかったのか。」
  エッセイでは体言止めも使う（「プロダクトアウトではなくマーケットイン。ズレたまま進んでは手戻りです。」）
- **よく出る語**: 「ちなみに」「もちろん」「要は」「いい感じ」「ハマりどころ」「フワッと」「腹落ち」
  「交通整理」「空中戦」「〜系です」「地味な領域」。「ぶっちゃけ」「（笑）」「余談ですが」は0回
- **英数字と日本語の間に空白を入れない**（693 対 186。空白ありは RFC の記事1本に集中）。
  バージョンは `Go 1.27` のように Go と数字の間だけ空ける

## 型

### 導入（`## はじめに`、17/28本）

1行目は名乗り。3通りのどれか。**自己紹介はこれだけ**で、経歴や前置きは書かない。

- `TIG真野です。`
- `TIG（Technology Innovation Group）の真野です。`
- `TIG DX所属の真野です。`

2行目で記事が何かを1文で言う。連載なら索引記事へのリンクを先に置く。

```markdown
TIG真野です。[Go 1.27 リリース連載](/articles/20260728a/)の2本目です。

Go 1.27で `go mod tidy` に追加された `require` ブロックの自動マージについて紹介します。
[リリースノート上は数行のさらっとした変更](https://tip.golang.org/doc/go1.27#go-mod-tidy)ですが、
2022年起票のIssueから約4年の経緯があります。

検証には `go1.27rc2 linux/amd64` を利用しました。
```

- 「〜してみた記事です」「〜について紹介します」「〜を解説します」「〜の発表です」
- **Go 連載は検証環境を1行で書く**（「検証は `go1.27rc2 linux/amd64` で行いました」）。
  Playground を用意したならここで案内する
- 名乗りの前に先頭画像（`top.jpg` / `unnamed.jpg`）が入る。寄稿・エッセイは名乗らずに
  状況描写から入ることもある（「正直に言うと、最初に編集部からオファーをいただいた時、〜」
  「リモートの会議が終わったら即『退出』ボタン。」）

### 本文

- **背景・経緯を1節置く。** 「出自」「黎明期（2016年〜）」のように、Issue 番号と年を添えて
  なぜ今こうなったかを語る。リリースノートの1行の裏にある数年の議論を掘るのがこの人の持ち味
- **比較は表。** ツールの立ち位置が掴みにくいときは「競合と比較すると輪郭が明確になる」として表で並べる
- **動かす記事は `## 動かしてみる` → `### 環境情報` → 項目ごとに `console` フェンス。**
  試す項目は先に太字ラベル付きの箇条書きで予告する（`- **rangeint:** \`for i := 0; …\` を \`for i := range 10\` に`）
- **箇条書きは2段まで。** 1段目を太字ラベル、2段目で説明（540項目）。番号付きは「3点」「3つの論点」のように
  数を先に言ってから
- **太字は主張の核だけ**（229回）。「本質的には「**実務で迷いやすかった部分のガイダンスが整理された**」」の形で、
  文の中の一句を囲む。見出しの太字化や、段落ごと太字にはしない
- **エッセイは具体的な台詞を鉤括弧で書く。** 「すみません、少し話が逸れました。関連する話ですが、
  これは別の論点ですね。」のように、会議でそのまま使える言い回しを置く。架空の場面を作るときは
  「（設定の作り込みの甘さはご了承ください）」と断る
- **読者への呼びかけは末尾に1つ。** 「〜してみてはどうでしょうか」「ぜひ〜に取り入れてみてください」。
  「みなさん」は3回しか使わない
- 脚注・`::: note` はほぼ使わない（各3回）。補足は丸括弧で本文に入れる

### 結び（`## まとめ` 14本 / `## さいごに` 9本 / `## おわりに` 4本）

1文目で「〜を紹介しました。」「〜を試しました。」と振り返り、要点を箇条書きで3つ前後。
その後に**私見を1〜2文**。最後の行は型が3つ。

- `最後まで読んでいただき、ありがとうございました！`（Go 連載・解説系）
- フィードバックの誘い（ガイドライン公開・活動報告）:
  「ぜひGitHubの[Issue](…)や[X](…)などでお寄せください」「Xなどでフィードバックいただけると嬉しいです」
- 次の行動の提案（エッセイ）: 「がんばりましょう。」「それでは良いPostmanライフを。」

私見の例（この温度で書く）:

> 個人的には互換性を重視すると思っているGoチームとして意外な動きな気がしており、少しドキドキのアップデートです。#80210の決着がどうなるか楽しみです。

> 差分が少ないこと自体が、この仕様がもう十分に枯れていることを示しているようで、個人的には読んでいて心地よい RFC の更新でした。

> 大規模ではハマりどころも多いのでテックリード的な視点では、現時点では禁止にしておきたい

ガイドライン公開の記事は、謝辞（関わった人の名前を列挙）→ リンクの再掲で終える。

### タイトルと lede

- タイトルは主題を名詞で言い切る。「Go 1.27の〜」「〜を公開しました」「〜Tips 9選」「〜についてSlackで話した」。
  問いかけ型（「なぜ〜か？」「〜はMakefileの代わりになるか？」）はエッセイ・試用記事に使う。
  副題は全角 ～ で挟む
- lede は1〜2文で「何の記事か」だけ。「Pikeを触ってみた記事です。」「go fixコマンドのアップデートについて解説します。」

## 書かないこと

- 「本記事では〜について解説していきます。それでは見ていきましょう。」のような
  AI 生成物に多い前置きと、節ごとの「〜について見てきました」の繰り返し
- 「〜することが重要です」「〜が求められます」の連続。この人は「〜と良さそうです」「〜しておきたい」と言う
- 全部を良い話にする。制約・ハマりどころ・未解決（「#80210の決着がどうなるか」）を残す
- 「筆者」「弊社」。「フューチャー」「私」「私たち」と書く
- 絵文字。「！」は1記事に1〜3個、締めと感動したところだけ

## 手順

1. 記事の型（Go 連載 / 試用 / ガイドライン公開 / エッセイ）を決め、導入と結びの型を上から取る
2. 本文を書いたら、`## 声` の各項目で読み直す。特に「段落が4文以上」「私見に『思います』『でしょう』が無い」
   「感情表現が3か所以上」「英数字の前後に空白」を直す
3. 既存の下書きを寄せる場合、**事実・構成・コード・図は動かさず、言い回しだけを変える**。
   「〜することが重要です」→「〜しておくと良さそうです」、「〜していきます」→「〜します」、
   前置き・繰り返しの削除、私見の追加（1〜2文、結びに）
4. `node_modules/.bin/textlint <path>` を通す。CLAUDE.md の記事の書き方（コードフェンス・画像・連載の規則）は
   この文体より優先する
